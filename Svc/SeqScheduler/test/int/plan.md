# QUAL-SEQSCHED — Svc.SeqScheduler on Ref

## 0 Scope
- Ref `configure` values the plan depends on: 16 rows, a tick period of 1 s (rate group 1 Hz) and a default table file that the plan overrides with `TABLE_FILE`, for both `seqSched` and `seqSchedB`.
- L0: desk-checked; bench confirmation pending.
- UUT: `Svc.SeqScheduler`, `lestarch-autobot/fprime` branch `seq-scheduler`; SHA recorded in the manifest.
- Test fixture: `Ref.TimeBaseSetter`, instance `timeBaseSetter`, between every component's time port and `posixTime`.
- Deployment: `TestDeploymentsProject/Ref`, the repository's full reference deployment, with `seqSched` -> `schedSeq` (`Svc.CmdSequencer`) and `seqSchedB` -> `schedSeqB`, both schedulers on the 1 Hz rate group, their channels in a new `SeqSched` telemetry packet.
- Bench: native Linux `Ref` and `fprime-gds` on the session VM, one file system shared by the image and the harness; no hardware, no power control. Restart = stop and start the `Ref` process.
- Ground system: `fprime-gds` from the UUT's `requirements.txt`; sequences built with `fprime-seqgen`; table files written by `Svc/SeqScheduler/scripts/seq_schedule_table.py`.
- Sequencer idle (require on every test) = every `CS_SequenceLoaded` or `CS_PortSequenceStarted` of this start of `Ref` in the record is followed by a complete or cancel event of the same sequencer before the test's opening marker.
- Parameters at plan values (require on every test) = for each parameter, the last `*_PRM_SET` command of this start in the record, with its `OpCodeCompleted`, carries the plan value, or none was sent since the start (the image starts from the plan's parameter file).
- Out of scope: `Svc.WasmSequencer` and FPy sequencers as the attached sequencer; uplink of table and sequence files (written directly to the shared file system).

## 1 Entry gates
- The harness sends each command only after the completion of the previous one is recorded, so the component queue (size 10) is never filled by commands.
- Unit tests of `Svc/SeqScheduler` pass with every row of the SDD unit-test list implemented; unit tests of the fixture `Ref/TimeBaseSetter` pass.
- `Ref` built from the manifest SHA; `fth verify-plan plan.json --tests .` passes.
- Marker round-trip: `CdhCore.cmdDisp.CMD_NO_OP_STRING("100")` logged as `Received a NO-OP string=100` (L0-1).
- Event budget: the busiest window (L2-14) raises under 50 events in 60 s; Ref's TCP downlink has no rate limit.
- Sequence files built and present: `short.bin` and `short2.bin` = two `CdhCore.cmdDisp.CMD_NO_OP` records, relative delay 0, no wait, run time under 2 s; `long.bin` = `CMD_NO_OP`, a 20 s relative wait, `CMD_NO_OP`. `missing.bin` absent. The dry run confirms the run times.
- A time base override does not stop the image: confirmed in L0-2, which runs short.bin under the override, before any other test. `Fw::Time` comparison across bases is `INCOMPARABLE`, not an assert (`Fw/Time/Time.cpp`), but a `Svc.CmdSequencer` wait started in one base never expires in another: no test changes the override while `long.bin` runs.
- Run order: L0-1, L0-2 first; L2-5 and L2-11 in the same start of `Ref` as the first report of their time base; L3-1 (restart) after them. The order is fixed, not drawn.

## 2 Test levels
L0 provenance/feasibility · L2 functional · L3 persistence/restart · L5 fault paths · L6 negative controls · L7 final state for independent verification. No L4: the component has no performance requirement.

## 3 Test entries

Window rule: rows from the **last** `cmdDisp.NoOpStringReceived(id=START)` row that precedes the first `cmdDisp.NoOpStringReceived(id=END)` row following it, through that END row plus the END `CdhCore.cmdDisp.CMD_NO_OP_STRING` command's own `cmdDisp` rows (at most two), inclusive; ordering key `t = epoch·1e6 + fsw`, archive index on ties. Channel rows are those with `t` between the first and last window event. `commands_sent` = commands from the matching START sending (its last sending if re-sent) through the END sending, inclusive.

Standard `complete` block (STD): both markers present; per opcode, every command sent in the window was dispatched once; only CMD_NO_OP, the command the sequence files hold, may be dispatched more often than sent (helper `commands_dispatched`); event cmdDisp.TooManyCommands count == 0; no sample of events.EventsDropped in the window differs from the last sample before it; with no earlier sample in the record, any non-zero sample in the window fails (helper `events_dropped_steady`); no sample of comQueue.comIngressDropped or comQueue.comManagedDropped in the window differs, in any element, from the last sample before it; with no earlier sample in the record, any sample in the window with a non-zero element fails (helper `com_dropped_steady`); SeqSched samples >= 2; event cmdDisp.OpCodeError count == 0.
